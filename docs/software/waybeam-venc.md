# Waybeam — Відеоенкодер для FPV

**Waybeam** — це автономний H.265 (HEVC) відеоенкодер і RTP-стрімер для камер на чіпах SigmaStar Infinity6E (Star6E), SigmaStar Infinity6C (Maruko) та HiSilicon Hi3516CV610. Розроблений спеціально для FPV-дронів із мінімальною затримкою та повним керуванням через HTTP API у реальному часі.

::: info Репозиторій
[https://github.com/OpenIPC/waybeam](https://github.com/OpenIPC/waybeam)

Сторінку звірено з версією **v0.73.3** (кінець серпня 2026), контракт API — **0.22.0**.
:::

::: warning Репозиторій перейменовано
У серпні 2026 репозиторій **`waybeam_venc` перейменовано на `waybeam`**. Стара адреса редіректить, тож наявні клони, форки й ремоути працюють без змін. Продукт, бінарник, конфіг (`/etc/waybeam.json`), init-скрипт і тарбол релізу всюди звуться просто `waybeam`. Стара назва ще трапляється в історичних документах, коментарях у коді, назві вкладки дашборда та імені експортованого конфіга.
:::

### Можливості

| Функція | Опис |
| :--- | :--- |
| **Кодек** | H.265 (HEVC) з режимами CBR / VBR / AVBR / FIXQP. Кодек жорстко зафіксований — поля `video0.codec` більше немає |
| **Стрімінг** | RTP-пакетизація; Compact UDP-режим (raw NAL units). Транспорти: `udp://`, `unix://`, `shm://`, **`frame-shm://`** (цілі кадри через shared memory, без RTP) |
| **HTTP API** | Зміна параметрів у реальному часі без перезапуску потоку; окремий **`/api/v1/live/set`** пише лише в оперативний конфіг, не зношуючи флеш |
| **Веб-панель** | Вбудований дешборд на порту 80: конфігурація, API-docs, ISP-тюнінг; власний дешборд можна підкласти в `/usr/share/www` |
| **mDNS-виявлення** | Камера сама анонсує себе в мережі: `waybeam.local` + унікальне `waybeam-<суфікс>.local` (секція `discovery`) |
| **ISP IQ** | SigmaStar — 62 ISP-параметри з export/import профілів; CV610 — 11 груп / 59 полів (власна схема відповіді) |
| **3A (AE/AWB)** | Єдиний движок: `isp.aeEngine` приймає **лише `"sdk"`**. Понад ним працює наглядовий потік, що тримає межі `isp.gainMin/Max` та `isp.shutterMinUs/MaxUs` |
| **ROI-кодування** | Пріоритет центру кадру для FPV |
| **Стійкість до втрат** | Resilience-пресети: intra-refresh (rolling GDR) + SVC-T пірамида посилань; з v0.64 — пресет **`ltr`** (максимум нереференсних кадрів при довгому GOP) |
| **Багатослайсове H.265** | `video0.sliceCount` (1..32) — втрата пакета псує ділянку кадру, а не весь кадр (усі три бекенди) |
| **Framing** | Цифровий зум 1.25×–4× + стабілізація `stab` / `stab-fill` (Kalman) на SigmaStar; рівень детектора `video0.stabAccuracy` |
| **Детекція об'єктів (NPU)** | Плагінний детектор на IPU/NPU: секція `detect`, DETECT-трейлер у RTP-sidecar, рамки на debug-OSD, гаряча заміна моделі без розриву потоку (Star6E + Maruko) |
| **QR-сканування на борту** | Luma-tap без OSD + ізольований `qr_decode`: камера декодує маркер із власного кадру (`/api/v1/qr/scan`) і віддає 16-символьний конверт. Логіку парування/команд поверх нього ще не реалізовано — Star6E |
| **Висока частота кадрів** | IMX335 — до 144 fps (`1600×900@144` на Star6E, `1536×864@144` на Maruko); IMX415 — до 120 fps (`1728×816@120`); IMX662 на CV610 — до 100 fps. Власні in-tree драйвери сенсорів |
| **Аудіо** | Захват звуку, кодеки Opus / G.711a / G.711µ / PCM (на CV610 — Opus 48 кГц моно) |
| **Snapshot** | Окремий MJPEG-канал — кадр через `/api/v1/snapshot.jpg` (усі три бекенди) |
| **Запис на SD** | MPEG-TS (HEVC + аудіо), безпечний у разі знеструмлення; з v0.70 запис винесено в **окремий потік**, тож він більше не гальмує ефір |
| **Gemini-режим** | Два VENC-канали: стрімінг + запис незалежно (Star6E та Maruko) |
| **Адаптивний бітрейт запису** | Авто-зниження бітрейту запису якщо SD-карта не встигає (10%/с) |
| **IMU** | Драйвер BMI270 (SigmaStar), вимкнений за замовчуванням; з v0.39 живить оцінку горизонту (attitude) |
| **Attitude (горизонт)** | Живі roll/pitch/yaw через `GET /api/v1/attitude`, калібрування рівня однією командою, ATTITUDE-трейлер у RTP-sidecar для HUD (Star6E) |

::: details Для версій до v0.8 — гіроскопна стабілізація GyroGlide (секція `eis`)
У старих версіях була гіроскопна стабілізація **GyroGlide-Lite** (секція конфігу `eis`). Її **видалено у v0.8.0**. Тепер стабілізація реалізована через Kalman-фільтр у полі `video0.framing` (`stab` / `stab-fill`) і не потребує IMU. Драйвер BMI270 лишився: з v0.39 він живить оцінку горизонту (attitude) для телеметрії/HUD, але не стабілізацію.
:::

::: details Для версій до v0.47 — `isp.aeEngine` мав значення `"custom"`
Раніше на Star6E поле `isp.aeEngine` приймало два значення — `"sdk"` і `"custom"` (userspace-AE), а на Maruko після v0.22 воно взагалі ігнорувалося. З'ясувалося, що потік `cus3a` ніколи не робив зведення AE — його завжди вів ISP-firmware/bin, в обох режимах. У **v0.47.0** значення `"custom"` **видалено повністю**: тепер приймається лише `"sdk"`, а старий конфіг зі `"custom"` завантажується з попередженням і відкатом на `sdk`. Наглядовий потік лишився, але тільки як «сторож меж» — він тримає `isp.gainMin/Max` і `isp.shutterMinUs/MaxUs` над штатною firmware-AE.
:::

::: details Для версій до v0.65 — лише два чіпи (SigmaStar)
До серпня 2026 Waybeam працював виключно на SigmaStar: Infinity6E (Star6E) та Infinity6C (Maruko). Третій бекенд — **HiSilicon Hi3516CV610 із сенсором Sony IMX662** — з'явився у **v0.65.0** (13 серпня 2026) і за серпень доведений майже до паритету. Якщо ви читали цю сторінку раніше — таблиця чіпів нижче була з двох рядків.
:::

### Підтримувані чіпи

| Чіп | Бекенд | Сенсори | Статус |
| :--- | :--- | :--- | :--- |
| SigmaStar Infinity6E | `star6e` | SSC30KQ, SSC338Q | ✅ Повна підтримка (еталонний бекенд) |
| SigmaStar Infinity6C | `maruko` | SSC378QE | ✅ Підтримка (кілька функцій — підмножина Star6E) |
| HiSilicon Hi3516CV610 | `cv610` | Sony IMX662 | 🟡 Стрімінг, запис, IQ, resilience — працюють; стабілізація, детекція, QR, attitude — ні |

::: info Кодек — лише H.265
Waybeam кодує тільки H.265 (HEVC) на всіх трьох чіпах. Поля `video0.codec` немає; старі конфіги з `"codec": "h264"` чи `"h265"` завантажуються без помилок, але ключ ігнорується.
:::

::: warning Що підтримує лише Star6E
- Scene-change IDR (`video0.sceneThreshold` / `sceneHoldoff`)
- Формат запису `hevc` (на Maruko та CV610 — лише `ts`)
- QR-сканування (`/api/v1/qr/*`; на Maruko — `404`)
- ATTITUDE-трейлер у RTP-sidecar та калібрування рівня (на Maruko `/api/v1/attitude/calibrate_level` повертає `501`)
- `/api/v1/dual/set` (на Maruko — `501`: інший layout структури venc-каналу)

Перевіряйте підтримку конкретного поля бекендом через `/api/v1/capabilities`.
:::

::: warning Чого ще немає на CV610
- Стабілізація та цифровий зум (`video0.framing`), детекція об'єктів, QR, attitude
- `video0.qpDelta` (прибрано у v0.73.0 — CBR-контролер CV610 його ігнорує; замість нього `video0.intraRefreshQp`)
- `record.mode: "dual"` / `"dual-stream"` (потрібен другий VENC-канал) — запит відхиляється з попередженням
- `/api/v1/iq/import` (експорт `/api/v1/iq` працює, але в іншій схемі відповіді)
:::

::: details Для версій до v0.35/v0.37 — стабілізація лише на Star6E
Раніше стабілізація `stab` / `stab-fill` працювала тільки на Star6E, а на Maruko відповідні контролі у WebUI були неактивні (вважалося, що детектор `MI_IVE` на цьому чипі не працює). У **v0.35** на Maruko запрацював `stab`, у **v0.37** — і `stab-fill`; причиною була несумісна vendor-бібліотека, яку тепер постачає тарбол. Нюанси на Maruko: детектор руху — програмний (NEON) і на одноядерному чипі коштує помітну частку CPU (рівень якості/ціни — поле `video0.stabAccuracy`, v0.36), а `stab-fill` несумісний з `record.mode: "dual"`.
:::

::: details Для версій до v0.70 — HTTP-керування записом вважалося Star6E-only
Раніше документація (і сам контракт API) стверджувала, що `/api/v1/record/start|stop` працює лише на Star6E, а Maruko повертає `501`. Це було **застаріле твердження**: Maruko опитує ті самі прапорці старту/зупинки, відколи зареєстрував `record_http_control_supported(true)`. У контракті **0.22.0** цей рядок виправлено. З **v0.70.0** запис доїхав і до CV610 — у режимі `record.mode: "mirror"`.
:::
